# Ferramentas de Teste: Postman e Insomnia

A fim de tornar sua experiência de integração com a Clicksign API ainda mais eficiente, disponibilizamos Collections para os populares aplicativos de teste de APIs, Insomnia e Postman. Essas ferramentas ajudam a economizar tempo e simplificar o processo de criação e envio de requisições para a API.

## Por que usar as Collections?

Nossas collections são projetadas para:

* Fornecer um guia prático de todos os endpoints da API, incluindo exemplos prontos para uso.
* Reduzir erros de configuração inicial, com parâmetros, headers e exemplos de payloads pré-configurados.
* Facilitar a adaptação e personalização das requisições de acordo com as suas necessidades específicas.

# Como Utilizar

## Insomnia

1. Faça o download da Collection para Insomnia clicando <a href="https://github.com/clicksign/docs-clicksign-api" target="_blank">aqui</a>.
2. Importe o arquivo no Insomnia:
   1. No aplicativo, clique em Create > Import > From File e selecione o arquivo baixado.
3. Configure sua API Key nos headers padrão, e você estará pronto para começar!

## Postman

1. Baixe a Collection para Postman através deste <a href="https://github.com/clicksign/docs-clicksign-api" target="_blank">link</a>.
2. No Postman, importe a collection:
   1. Clique em Import > File e selecione o arquivo da collection.
3. Configure sua API Key como uma variável de ambiente para facilitar o uso nos endpoints.

## O que está incluído?

Nossas collections incluem exemplos detalhados para os principais recursos da Clicksign API:

* Envelopes: Criar, editar, ativar e consultar envelopes.
* Documentos: Adicionar, atualizar e gerenciar documentos nos envelopes.
* Signatários: Adicionar, editar e remover signatários em um envelope.
* Notificações: Gerenciamento de notificações enviadas aos signatários.
* Observadores de Assinatura: Gerenciar quem pode acompanhar a assinatura mesmo que não faça parte do processo de assinatura.
* Gestão de Usuários e Membros: Quando a conta está com SAML/SSO ativo, é possível gerenciar usuários e acessos através do endpoint da API.
* Todos os exemplos estão acompanhados de informações sobre os parâmetros necessários, headers obrigatórios e respostas esperadas da API.
